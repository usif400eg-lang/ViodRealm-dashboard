Set up the dashboard

Fully static — no build step, no backend.

1. Firebase web app

Create a Web app in the Firebase Console and copy its config into firebase-config.js.

Enable Email/Password, Google, or GitHub under Authentication, and create your first admin user.

2. Publish rules

In Realtime Database → Rules, paste firebase-rules.json and Publish.

# Editing the file locally does not
# deploy rules — publish in the Console.

3. Run or deploy

# Local preview (serve over HTTP)
python -m http.server 8000
# then open http://localhost:8000

Deploy to any static host (Render, Netlify, GitHub Pages). Build command: empty; publish directory: .

Secure by design

The dashboard never holds the Firebase service account. Access is enforced by Auth + Realtime Database Security Rules.

🔑

Token authorization

Each server gets a unique id and secret token. The plugin proves it holds a matching token and never writes it back.

⏱️

Instant revocation

The plugin live-watches its token. Revoke or rotate it from the panel and syncing stops within seconds — never crashing the server.

🧩

Duplicate detection

A per-boot instance id exposes fake or duplicated connections that reuse the same credentials.

🛡️

Owner-scoped rules

Server metadata is owner-writable only; the auth token is readable solely by its owner; presence fields are read-only to clients.

🙈

Public config is safe

firebase-config.js holds public project identifiers, not secrets. Real security is in Auth + Rules.

🔒

Keys stay off the web

The Admin service account key belongs on the server only and is git-ignored — never shipped to the browser.
